## Inconsistencies in code, schema or panel that you should know about

1. `pity_every`: the schema description ("has not given a good car or better this many times in a row gives one the next time") is off by one against the code and the web text. The code (`$sinceGood + 1 >= pity_every`) guarantees the 15th opening after 14 misses (docs agree: "po 14 magazynach ... 15. jest dobre"). The catalog follows the code.
2. (SUPERSEDED after the unit-detection fix: the 11 entries `exchange/defect_ppm/min|max`, `pricing/class_floor_ppm/*`, `storage/classes/*/condition_ppm/min|max` are now written in percent, label "(%)", no ppm explanation. The text below is the old state.) Units in the Studio: these ppm numbers were `Plain` in the input, so the operator must type raw ppm (e.g. 150000): `exchange/defect_ppm/min|max`, `pricing/class_floor_ppm/*`, `storage/classes/*/condition_ppm/min|max`. Other ppm numbers of the same section are `Percent` (`age_kept_ppm`, `mileage_floor_ppm`, `condition_base_ppm`, `description/*`, `inspection_ppm`, `resale_ppm`). The help for the Plain ones says "w ppm: 1 000 000 = 100%" and labels carry "(ppm)". Making them `Percent` would be kinder.
3. `storage/classes/*/condition_ppm/*` have no upper limit in the schema (`range` def has only minimum 0). A value above 1 000 000 makes the defect count negative (`round((1e6 - condition) / 200000)`); the price code clamps it but `defects` does not.
4. The schema does not enforce: min <= max in any range, `good_from_ppm >= fair_from_ppm`, ascending `up_to_km`, at least one odds weight > 0, and (for the guarantee) good + gem weight > 0 per unit kind. With a bad value the draw breaks (`between()` with max < min, `array_sum` of 0). The texts say what must hold.
5. The dealer screen text is hard-coded in the web locales (`market.dealerSub`, `market.dealerNew`: "przebieg 0-15 km"), so it will not follow `dealer_mileage_km`.
6. The storage pool takes every ICE car of the pack with `min_player_level <= pool_level` regardless of its `sources`, while the exchange needs the source `exchange`. A car without the exchange source can still be found in a unit.
7. `exchange/defects/*/weights/*`: the panel label_now is "Weights 1", counting from 1, but position 1 is "0 defects". The catalog label is generic ("Waga liczby usterek") and the help explains the position; the panel could show "0 defects", "1 defect" ... instead.
8. Entries with a star in the middle (`class_floor_ppm/*`, `units/*/...`, `defects/*/...`) have generic labels by design; the panel must keep showing the name of the class/unit/band next to them (the group title does today: "Storage › Units › Small").
9. `docs/api-runs.md` and `content/README.md` call the odds "w promilach"; the code treats them as relative weights (normalised by their sum). They only read as per mille because the starter sums are exactly 1000. The help says both.
